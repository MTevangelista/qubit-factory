# qubit v0.2.0

Data: 2026-11-10 · MR: [#2](https://github.com/MTevangelista/qubit-factory/pull/2) (`feat/software-factory`)

A fábrica deixa de fazer merge localmente: agora ela publica a branch do job e abre o MR, e o merge fica com uma pessoa, no remoto.

## Novidades

- **Etapa MR no lugar do merge local.** Depois do `APPROVE` (ou de `/qubit approve <job-id>`), o orquestrador abre o MR da branch do job para a branch base (`FACTORY_BASE_BRANCH`) e para. Novo status final: `mr-open`; o link fica em `job.json.mr`.
- **Branch do job em conventional commits:** `<type>/<job-id>` (`feat/`, `fix/`, `refactor/`), no lugar de `factory/<job-id>`.
- **Push da branch do job:** logo depois de criar a branch e depois de cada commit do builder.
- **Novo `guard_push.py`** (interpreta o comando com `shlex`): libera push comum, mas continua bloqueando force push, `--all`/`--mirror` e push em `master`, `main` ou `FACTORY_BASE_BRANCH`.

## Mudanças

- `factory-init` não nega mais `git push` e remove a regra de deny antiga.
- `CLAUDE.md`, templates, READMEs, diagrama do fluxo e dashboard atualizados para o novo fluxo.
- Autoteste da fábrica estendido para cobrir a guarda de push.
- Versão do plugin: `0.1.0` → `0.2.0`.

## Atenção ao atualizar

- Projetos que usavam branches `factory/<job-id>` passam a usar `<type>/<job-id>`.
- Quem esperava o merge automático agora precisa fazer o merge do MR no remoto.
- Rode `factory-init` de novo para remover a regra de deny de `git push` das configurações do projeto.
